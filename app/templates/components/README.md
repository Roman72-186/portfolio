# components/ — общие блоки интерфейса

Здесь живут Jinja-макросы, из которых собираются экраны: карточка недели, плитка
задания, полоса прогресса, статус-бейдж и всё остальное, что встречается больше
чем на одной странице.

Зачем отдельная папка. На 21.08.2026 в проекте было 10 макросов на 54 страницы —
почти каждый экран собирался с нуля, и один и тот же блок расходился между
кабинетами на первой же правке. Кабинетов впереди четыре: ученик, преподаватель,
суперадмин, куратор. Без общих блоков это четыре независимых интерфейса.

## Правила

- **Один блок — один файл**, имя по назначению: `week_card.html`,
  `task_tile.html`, `progress_bar.html`.
- **Макрос принимает данные, а не решает, кто на него смотрит.** Права и
  фильтрация остаются в сервисе и роуте, блок только рисует то, что дали.
- **Стили — в `base.css` или в файле экрана**, не в `<style>` внутри макроса.
  За этим следит `tests/test_reuse_ratchet.py`.
- **Разный вид у одного блока — модификатор класса**
  (`.task-tile--compact`), а не второй макрос-копия.

## Как подключить

```jinja
{% from "components/week_card.html" import week_card %}
{{ week_card(week, can_open=True) }}
```

`{% from %}` берёт конкретный макрос, `{% include %}` вставляет файл целиком —
для блоков с параметрами нужен первый.

## Что записать после

Новый общий блок дописывается в `../../../../docs/component-map.md`, иначе
следующий человек его не найдёт и напишет свой.

Контракт целиком — `../../../../docs/reuse-contract.md`.
